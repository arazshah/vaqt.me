# استقرار «وقت من» روی Coolify

این راهنما برای سروری است که Coolify روی آن نصب است. کل مجموعه (سایت، API، دیتابیس) با یک فایل
`docker-compose.coolify.yml` بالا می‌آید و **تنها چیزی که در Coolify تنظیم می‌کنید دامنه است.**
تنظیمات پیامک و ربات بله بعداً از داخل خود سایت (پنل مدیریت) انجام می‌شود.

## ۱. پیش‌نیاز

- یک دامنه (مثلاً `vaqt.me`) که رکورد `A` آن به IP سرور اشاره می‌کند.
- Coolify روی سرور، و اتصال آن به GitHub (GitHub App یا deploy key).
- مخزن `arazshah/vaqt.me` (برنچ `main` پس از merge شدن کارها؛ تا آن موقع می‌توانید خود برنچ کاری را انتخاب کنید).

## ۲. ساخت منبع (Resource)

1. در Coolify: **Project → New Resource → Public/Private Repository (with GitHub App)**.
2. مخزن و برنچ را انتخاب کنید.
3. **Build Pack** را روی **Docker Compose** بگذارید.
4. **Docker Compose Location** را بنویسید: `/docker-compose.coolify.yml`
5. روی **Continue** بزنید تا Coolify فایل را بخواند و سه سرویس را نشان دهد: `web`، `api`، `postgres`.

## ۳. دامنه

فقط به سرویس **`web`** دامنه بدهید، با `https`:

```
https://vaqt.me
```

سرویس‌های `api` و `postgres` دامنه ندارند و از بیرون در دسترس نیستند (API فقط از طریق `web` و
مسیرهای `/api` و `/uploads` کار می‌کند). به همین دلیل CORS و مشکل کوکی ندارید.

> فایل compose مقدارهای زیر را خودکار می‌سازد و **لازم نیست دستی وارد کنید**: رمز دیتابیس، `APP_SECRET`
> (کلید اصلی رمزنگاری؛ OTP و JWT از آن مشتق می‌شوند) و آدرس سایت (`WEB_ORIGIN`).

## ۴. Deploy

دکمه‌ی **Deploy** را بزنید. بار اول چند دقیقه طول می‌کشد (ساخت دو ایمیج). هنگام بالا آمدن `api`،
مهاجرت‌های دیتابیس خودکار اجرا می‌شوند؛ نیازی به دستور دستی نیست.

برای به‌روزرسانی‌های بعدی: کد را به همان برنچ push کنید و (اگر auto-deploy فعال است) خودکار، وگرنه دستی Deploy بزنید.

## ۵. ساخت اولین مدیر

تا وقتی هیچ مدیری وجود ندارد، `api` موقع هر بار بالا آمدن یک **توکن یک‌بارمصرف** در لاگ چاپ می‌کند:

1. در Coolify به **Logs** سرویس `api` بروید.
2. خطی مثل زیر را پیدا کنید و توکن را کپی کنید:

   ```
   ================ FIRST-RUN ADMIN SETUP ================
     Open:  https://vaqt.me/admin/setup
     ADMIN SETUP TOKEN: xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
   ```

3. آدرس `https://vaqt.me/admin/setup` را باز کنید، توکن و **شماره‌ی موبایل خودتان** را وارد کنید.
   همان لحظه مدیر ساخته می‌شود و وارد پنل می‌شوید (بدون نیاز به پیامک).

نکته‌ها: توکن با ری‌استارت `api` عوض می‌شود، فقط یک بار کار می‌کند و بعد از ساخته شدن مدیر، آن صفحه خودش
غیرفعال می‌شود. اگر دسترسی مدیر را از دست دادید، با دسترسی به دیتابیس می‌توان `systemRole` یک کاربر را
`ADMIN` کرد.

## ۶. تنظیمات داخل پنل (`/admin/settings`)

همه‌ی مقدارها بلافاصله بعد از «ذخیره» اعمال می‌شوند؛ ری‌استارت لازم نیست. مقدارهای محرمانه (کلید API،
توکن ربات) رمزنگاری ذخیره می‌شوند و هرگز دوباره نمایش داده نمی‌شوند.

### پیامک (sms.ir)

تا وقتی تنظیم نشود، **هیچ کدی ارسال نمی‌شود** و صفحه‌ی ورود پیام «ارسال پیامک هنوز راه‌اندازی نشده» را نشان می‌دهد.

1. در پنل sms.ir یک الگوی «verify» با یک متغیر به نام `CODE` بسازید و شناسه‌ی عددی‌اش را یادداشت کنید.
2. در پنل «وقت من»: سرویس‌دهنده را روی **sms.ir** بگذارید، **کلید API** و **شناسه‌ی الگوی کد ورود** را وارد کنید.
3. با «پیامک آزمایشی» یک پیامک به شماره‌ی خودتان بفرستید.
4. برای پیامک‌های رزرو، در sms.ir پنج الگو بسازید و شناسه‌ها را در بخش «الگوهای پیامک رزرو» بگذارید
   (متغیرهای هر الگو زیر هر فیلد نوشته شده). الگوی خالی یعنی همان پیامک ارسال نمی‌شود.

### ربات بله

1. در بله از `@botfather` یک ربات بسازید و **توکن** را بگیرید.
2. در پنل: ربات بله را روی **بله** بگذارید، توکن را وارد و **ذخیره** کنید.
3. دکمه‌ی **«اتصال و ثبت وبهوک»** را بزنید. این دکمه توکن را با بله چک می‌کند، نام کاربری ربات را خودش پر
   می‌کند و آدرس وبهوک را در بله ثبت می‌کند (آدرس سایت باید `https` باشد).
4. هر متخصص از صفحه‌ی «رزروها» دکمه‌ی «اتصال به بله» را می‌زند و کد را برای ربات می‌فرستد.

## ۷. پشتیبان‌گیری

داده‌ها در دو volume هستند: `pgdata` (دیتابیس، شامل صف و کش) و `uploads` (تصاویر پروفایل).
مهم‌ترین مورد دیتابیس است. نمونه‌ی پشتیبان دستی روی سرور:

```bash
docker exec $(docker ps -qf name=postgres) pg_dump -U vaqt vaqt | gzip > vaqt-$(date +%F).sql.gz
```

(در Coolify می‌توانید همین دستور را به‌صورت Scheduled Task روی سرویس `postgres` هم تعریف کنید.)
**`APP_SECRET` را عوض نکنید:** کلیدهای ذخیره‌شده در پنل با آن رمزنگاری شده‌اند و با تغییرش باید دوباره وارد شوند.

## ۸. اگر سرور داخل ایران است

- Docker Hub و npm ممکن است از سرور در دسترس نباشند. برای ساخت ایمیج‌ها یک registry mirror برای Docker
  (در `/etc/docker/daemon.json`، کلید `registry-mirrors`) و یک mirror برای npm لازم است. این‌ها تنظیم سرور
  هستند، نه پروژه.
- ایمیج‌های پایه: `node:22-alpine` و `postgres:16-alpine`.
- ربات تلگرام و واتس‌اپ عمداً پشتیبانی نمی‌شوند (سرور ایرانی به آن‌ها دسترسی ندارد)؛ فقط لینکشان روی کارت می‌آید.

## ۹. عیب‌یابی

| علامت                                                  | علت محتمل و راه‌حل                                                                                                                          |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------- |
| ورود یا ثبت‌نام خطای `FORBIDDEN` می‌دهد                | `WEB_ORIGIN` سرویس `api` با آدرس واقعی سایت یکی نیست. در **Environment Variables** منبع، `SERVICE_URL_WEB` باید `https://دامنه‌ی-شما` باشد. |
| صفحه‌ی ورود «ارسال پیامک هنوز راه‌اندازی نشده» می‌گوید | بخش «پیامک» پنل را کامل کنید (بخش ۶).                                                                                                       |
| `api` بالا نمی‌آید و `unhealthy` است                   | لاگ `api` را ببینید؛ معمولاً اتصال به `postgres` یا خطای مهاجرت است.                                                                        |
| تصاویر پروفایل پس از Deploy نمی‌آیند                   | volume `uploads` باید به سرویس `api` وصل باشد (در compose هست؛ آن را حذف نکنید).                                                            |
| ربات بله پیام نمی‌دهد                                  | «اتصال و ثبت وبهوک» را دوباره بزنید؛ سایت باید با `https` و گواهی معتبر باز شود.                                                            |

## ۱۰. چه چیزی تأیید شده و چه چیزی نه

با Docker واقعی، هر چهار سرویس از فایل compose ساخته و اجرا شد: مهاجرت‌ها روی دیتابیس خالی، ساخت مدیر اول،
ورود، آپلود تصویر، رندر سمت سرور و پراکسی `/api` همگی درست کار کردند. **روی خود Coolify** اجرا نشده است؛
متغیرهای جادویی `SERVICE_URL_WEB`، `SERVICE_PASSWORD_*` و `SERVICE_PASSWORD_64_*` طبق مستندات Coolify
نوشته شده‌اند و اگر در نسخه‌ی شما نام یا رفتارشان فرق داشت، همین فایل تنها جای اصلاح است.
اتصال واقعی به sms.ir و بله هم هنوز با کلید/توکن واقعی امتحان نشده است.
